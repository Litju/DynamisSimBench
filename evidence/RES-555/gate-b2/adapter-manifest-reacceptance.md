## 3. Actual implemented behavior and its limits

- `protected_profile.py` fixes the two approved 13-file SHA-256 values inside the protected
  execution profile and retains the separately approved legacy 10-file wire digests.
- `protected_launch.py` reconstructs `dynamisbench.mujoco.implementation-identity/2`
  from the measured runtime snapshot at route construction, again before each launch,
  and after exit. A missing, altered or unexpected bound file is an admission refusal
  or failed terminal correlation; the supervisor record includes the
  `production_entry_identity` check with the independently observed digest.
- `test_protected_adapter_manifest.py` verifies each accepted platform digest against
  the committed candidate and tests mutation of adapter physics, worker, contracts and
  bootstrap bytes and absence of the worker.

**Compatibility qualification:** WorkerRequest/WorkerResponse v1 is unchanged, including
its historical 10-file `adapter.implementation_digest`. The new 13-file hash is
separately enforced by the *supervisor*. It is **not** a claim that the worker-authored
protocol-v1 adapter field carries schema-2; the independent human reviewer must assess
whether this precise dual-binding satisfies the conditionally accepted replacement intent.
Rewriting the hashed worker or contracts to change the wire value would invalidate the
owner-accepted source digests and require a new explicit decision.

Nothing here authorizes the PR #35 merge, arbitrary-model execution, product API/CLI/UI
activation, native output, canonicalization, assessment or sealing. ADR-027 remains proposed.
